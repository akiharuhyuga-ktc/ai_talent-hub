## 等級定義

### B2（ジュニア）

**担当範囲**: 指定されたタスク・機能の実装

| 評価軸 | 期待される行動・成果 |
|--------|-------------------|
| 技術力 | 仕様に基づいてコードを実装し、コードレビューで指摘された点を修正できる |
| 自律性 | 不明点をすぐに確認・質問し、手戻りを最小化できる |
| チームへの貢献 | チームの規約・基準を守り、レビュー依頼・マージを適切なタイミングで行える |
| 成長 | フィードバックを素直に受け取り、同じ指摘を繰り返さない |

### B3（ミドル）

**担当範囲**: 担当機能・ドメインの自律的な設計・実装

| 評価軸 | 期待される行動・成果 |
|--------|-------------------|
| 技術力 | 担当機能の設計上の選択肢を提示し、トレードオフを説明できる |
| 自律性 | スプリントのタスクを自己管理し、ブロッカーを自ら解消または早期にエスカレーションできる |
| チームへの貢献 | コードレビューで建設的なフィードバックを出せる。ドキュメントを自発的に整備できる |
| 成長 | 自分の強みと課題を言語化し、成長のために自ら行動を起こせる |

### B4（シニア）

**担当範囲**: チームの技術基盤・標準の設計と後輩育成

| 評価軸 | 期待される行動・成果 |
|--------|-------------------|
| 技術力 | 複数の技術選択肢を比較・評価し、チームの技術方針を提案・決定できる |
| 自律性 | 曖昧な課題から問題を構造化し、解決の道筋を自ら設計できる |
| チームへの貢献 | 後輩の育成を継続的に支援し、チーム全体の技術力底上げに貢献できる |
| 影響範囲 | 担当チームを超えた技術課題に主体的に関与し、横断的な改善を起こせる |

### B5（リード）

**担当範囲**: 複数チームにまたがる技術戦略と組織課題の解決

| 評価軸 | 期待される行動・成果 |
|--------|-------------------|
| 技術力 | 中長期の技術ロードマップを描き、組織全体の技術方向性を設計できる |
| リーダーシップ | 複数のチームや関係者をまとめ、大きな技術課題を解決まで導ける |
| チームへの貢献 | 組織の技術文化・採用基準・育成方針の策定に中核的に関与できる |
| ビジネス貢献 | 技術的投資の判断にビジネス視点を組み込み、ROIを説明できる |

## 評価サイクル

- **半期評価**（4〜9月 / 10〜3月）：目標達成度とプロセスの両面で評価
- **中間確認**（3ヶ月時点）：期末評価に向けたすり合わせと軌道修正
- **昇格判定**：年1回（10月期末評価時点）を基本とする

## 評価の観点

### 短期成果評価（①）
設定した目標の達成状況。定量指標・定性指標それぞれで評価する。

- **S**: 目標を大幅に超える成果を達成し、チームへの影響も大きかった
- **A**: 目標をほぼ達成し、期待通りの成果を出した
- **B**: 目標の一部は達成できたが、想定より下回る部分があった
- **C**: 目標を達成できず、改善が必要

### 発揮能力評価（②）
目標達成のプロセスや、チームへの働きかけの質を評価する。

- **S**: 担当領域を超えてチーム全体に良い影響を与え続けた
- **A**: 担当領域での期待通りの動きができ、チームへの貢献も見られた
- **B**: 担当領域では動けたが、周囲への働きかけはまだ発展途上
- **C**: 担当領域での自律的な行動がまだ不十分
